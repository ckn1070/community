# 행동·절차 설명

행동 이름을 설명으로 대신하지 않습니다. 사용자가 `누가·언제·어디서`를 모두 쓰지
않았어도, 행동·절차를 묻거나 답변이 행동을 하나라도 제시하면 이 계약을 적용합니다.

## Admission

현재 존재 여부, 제안 여부와 추천 topology는 상위 판정에서 이미 고정된 값으로 받습니다.
이 문서는 없는 interface를 설계하거나 후보를 제외하지 않고, 선택된 현재 경로나 명시적인
제안의 행동을 빠짐없이 설명하는 형식만 소유합니다.

추가·변경·삭제·실행·배포·검증을 각각 독립 행으로 만들고, 다음 값을 source와 활성
결정에서 먼저 닫습니다. 다른 행이나 앞 문단의 값을 상속하지 않습니다.

```text
행동 | 현재 존재 / 미구현 | actor | 시작 event·전체 순서의 위치 | 실행 위치
| exact artifact·executable·API | 입력 interface | 직접 대상·행위
| 완료 관찰 | 부분 실패 복구
```

## 현재 구현된 경로

모든 값이 닫힌 행동만 사용자에게 보여 줍니다. 두 단계 이상이면 다음 열을 가진 표를
반드시 출력합니다.

```text
행동 | 누가·언제·어디서 | 실제 수단·입력 | 직접 대상·결과 | 실패·복구
```

각 행만 읽어도 완전한 문장이 되게 씁니다. `목록에 추가`, `코드를 배포`, `script 실행`,
`정상 동작 확인` 같은 동작명, 화살표와 인접한 행은 빠진 값을 대신하지 않습니다. 표
밖에서는 정의·이유·trade-off만 설명하고 새 행동을 추가하지 않습니다.

## 미구현 경로

현재 수단이 없다고 판정된 행동은 절차로 펼치지 않습니다. 사용자가 설계를 요청하지
않았다면 다음 card로 현재 공백만 출력합니다.

```text
현재 <행동>을 수행하는 저장소 수단은 없습니다.
- 실행 actor: <확정값 또는 미확정>
- 시작 event·순서: <확정값 또는 미확정>
- 실행 위치: <확정값 또는 미확정>
- executable·API: <확정값 또는 미확정>
- 입력 interface: <확정값 또는 미확정>
- 직접 상태 전이: <확정값 또는 미확정>
- 완료 관찰: <확정값 또는 미확정>
- 부분 실패 복구: <확정값 또는 미확정>

따라서 이 값들이 결정되기 전에는 실행 절차가 성립하지 않습니다.
```

`미정`만 적지 않고 무엇이 미정인지 각 field에 표시합니다. 사용자가 설계 대안을 요구한
경우에는 제안 후보의 interface를 `제안`으로 명시할 수 있지만, 현재 실행 절차로 표현하지
않습니다.

## False-block 경계

단순 정의나 한 단계 현재 사실은 표나 card를 만들지 않고 직접 답합니다. 사용자가 묻지
않은 구현·운영 lifecycle을 열지 않습니다.

## 최종 역대조

초안 뒤 새로 생긴 모든 행동 동사를 다시 수집합니다. 각 동사는 현재 구현 표의 한 행,
미구현 card 또는 삭제 중 하나여야 합니다. 셋 중 어디에도 없으면 답변을 내보내지
않습니다.
