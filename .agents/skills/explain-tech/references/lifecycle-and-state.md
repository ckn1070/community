# Lifecycle·상태 전이 설명

Phase 이름을 순서대로 나열한 것을 lifecycle 설명으로 계산하지 않습니다. 동일한 값이나
설정이 시간에 따라 어느 상태에 남고 어떤 event에서 다시 읽히는지 설명합니다.

## 비교 admission

전체 lifecycle, 변경 반영, `있고 없고의 차이`를 물으면 답변 전에 다음을 닫습니다.

```text
비교하는 exact 방식
| 바꾸는 설정 원본·desired state
| 변경 순간의 기존 실행 인스턴스 상태
| 변경 후 새로 만들어진 인스턴스 상태
| 기존 실행 상태를 끝내고 새 상태를 만드는 exact event·actor
| 두 방식에서 정말 다른 것과 같은 것
```

첫 문단에서 `무엇이 다르고 무엇은 동일한지`를 먼저 답합니다. 새 인스턴스의 결과로
기존 인스턴스의 변경 반영을 대신하지 않습니다. 원본 파일 편집, API의 desired state
변경, rollout·restart·reconcile와 실행 인스턴스 교체를 `수정`이나 `반영`하는 한 단어로
합치지 않습니다.

세 상태 이상이거나 비교 대상이 두 개면 다음 열의 작은 표를 사용합니다.

```text
event | 설정 원본·desired state | 기존 실행 상태
| 새 실행 상태 | 방식별 차이·공통점
```

## 후속 질문 repair

사용자가 같은 결론을 다시 묻거나 `그럼 기존 실행은 어떻게 알아?`, `수정하지
않는다며?`처럼 이전 전제를 지적하면, 새 질문을 국소 보충으로 처리하지 않습니다.

1. 현재 질문의 답을 첫 문장에 둡니다.
2. 직접 선행 대화의 원래 질문 행을 다시 열고, 아직 직접 답하지 않은 행을 유지합니다.
3. 이전 설명의 모순되는 전제와 그에 의존한 문장을 폐기합니다.
4. 최초 누락부터 원래 질문의 결론까지 전체 설명 단위를 교체합니다.
5. 원래 질문 행을 모두 닫은 뒤에만 추천·변형·추가 lifecycle을 엽니다.

두 번째 재질문이면 직전 답변을 수정하지 말고, 최초 원문 질문에서 전체를 다시 작성합니다.

## 경계

단순 정의·단일 현재 사실은 lifecycle 표나 repair를 열지 않고 직접 답합니다. 실행 단계를
제시하면 [action-and-procedure.md](action-and-procedure.md)를 함께 적용합니다. 현재 source에 없는 actor·script·
시작 event를 lifecycle 설명을 완결하기 위해 만들지 않습니다.
