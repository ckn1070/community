# 차량과 분리해 시작하는 일반 커뮤니티

## 상태

Proposed

## 계획 단계

결과 정의

## 달성할 결과

차량 관련 기능이나 데이터가 없어도 독립적으로 사용할 수 있는 일반 커뮤니티의 첫 범위를
정합니다. 현재에는 커뮤니티의 핵심 기능만 선택하고, 나중에 차량 관계나 커뮤니티 기능을
추가할 때 이미 정한 핵심 사용자 경험을 폐기하거나 차량 전용 커뮤니티로 교체하지 않습니다.

## 범위

- 차량과 연결하지 않고 먼저 제공할 일반 커뮤니티의 제품 범위
- 첫 출시에서 대화가 이루어지는 최소 콘텐츠 계층
- 이후 차량 관계와 추가 커뮤니티 기능이 기존 핵심과 함께 존재할 수 있다는 제품 수준 경계

## 제외 범위

- 현재 출시 범위의 차량·브랜드·모델·세대·트림 연결 기능
- 결과 정의가 닫히기 전의 API, schema, module, transaction과 구현·검증 task
- 아직 선택하지 않은 커뮤니티 기능을 현재 범위에 포함하거나 영구 제외하는 결정

## 요구사항

1. 현재 일반 커뮤니티는 차량 관련 기능과 데이터에 의존하지 않습니다.
2. 미래의 차량 연결은 일반 커뮤니티를 대체하지 않고 기존 핵심에 관계를 추가하는 방식으로
   제품 범위를 확장할 수 있어야 합니다.
3. 현재에는 핵심 기능만 선택하되, 이후 커뮤니티 기능이 추가돼도 먼저 확정한 핵심 사용자
   경험을 다시 정의하지 않아야 합니다.
4. 제품 결과 결정은 한 번에 하나씩 확정하고, 현재 결정을 본문에 반영한 뒤 다음 결과
   결정을 엽니다.
5. 첫 출시 화면의 콘텐츠 계층은 게시글·댓글·1단 답글로 구성하며, 답글을 2단 이상으로
   중첩해 표시하지 않습니다.
6. 1단 제한은 현재 출시의 사용자 경험이며, 이후 필요해진 답글 깊이나 표시 방식 확장을
   기존 게시글·댓글·답글 경험의 교체 없이 수용할 수 있어야 합니다.

## 수용 기준

- 현재 범위만 읽어도 차량 기능이 포함되지 않는다는 점과 미래 차량 관계가 폐기된 것이
  아니라는 점을 구분할 수 있습니다.
- 현재 핵심 기능과 미래 확장 기능을 구분하고, 미래 기능이 기존 핵심을 대체하지 않는다는
  경계를 제품 결과로 확인할 수 있습니다.
- 사용자는 게시글에 댓글을 달고 특정 댓글 아래에서 한 단계의 답글을 볼 수 있으며, 화면에
  2단 이상의 답글 계층은 나타나지 않습니다.
- 현재 1단 제한과 미래 확장 가능성을 구분할 수 있고, 현재 결과가 무제한 대댓글이나 다단계
  화면을 포함하지 않는다는 점을 확인할 수 있습니다.
- 활성 결정은 하나뿐이며, 선택되지 않은 CRUD 범위·공개 범위·게시판 수·부가 기능을
  확정하거나 제외한 것으로 기록하지 않습니다.
- 모든 결과 결정이 닫히기 전에는 해결 설계나 실행 계획으로 전환하지 않습니다.

## 결과 결정

### 확정

- 현재 일반 커뮤니티에는 차량 관련 기능을 넣지 않습니다.
- 미래 차량 관계는 기존 일반 커뮤니티 핵심을 교체하지 않는 추가 기능이어야 합니다.
- 현재에는 핵심 커뮤니티 기능만 정하고, 추가 커뮤니티 기능을 수용할 수 있는 제품 경계를
  유지합니다.

#### 첫 출시의 콘텐츠 계층

- 배경: 첫 커뮤니티에서도 사용자가 특정 댓글에 직접 응답할 수 있어야 하지만, 무제한으로
  깊어지는 답글은 대화 가독성과 운영 복잡도를 키울 수 있습니다.
- 검토한 선택지: 게시글만 제공하는 방식, 게시글과 평면 댓글을 제공하는 방식,
  게시글·댓글·1단 답글을 제공하는 방식과 여러 단계로 계속 중첩하는 방식을 비교했습니다.
- 비교 근거: 유명 서비스도 하나의 계층을 공통 표준으로 사용하지 않습니다. YouTube는
  [최상위 댓글과 그 답글](https://developers.google.com/youtube/v3/docs/commentThreads)을
  한 스레드로 묶고, Reddit은 댓글이
  [게시글 또는 다른 댓글을 부모로 가질 수 있는 구조](https://developers.reddit.com/docs/api/redditapi/models/classes/Comment)를
  사용합니다. GitHub Discussions는
  [댓글의 답글 대상과 스레드 답글](https://docs.github.com/en/graphql/guides/using-the-graphql-api-for-discussions)을
  제공하고, Discourse는 기존 평면 대화와 별도로
  [중첩 답글 보기](https://meta.discourse.org/t/introducing-nested-replies/402812)를
  도입했습니다. 따라서 서비스 규모만 따라가기보다 현재 대화 목적과 운영 범위로 깊이를
  정합니다.
- 선택: 게시글·댓글·1단 답글을 제공하고 현재 화면에는 2단 이상의 답글 계층을 표시하지
  않습니다. 이는 현재 출시의 표시 제한이며 미래에도 더 깊은 답글을 금지한다는 결정은
  아닙니다.
- 선택 근거: 특정 댓글을 대상으로 한 자연스러운 대화를 처음부터 지원하면서도 답글 깊이를
  한 단계로 제한해 가독성과 운영 범위를 통제할 수 있습니다. 평면 댓글로 시작한 뒤 답글을
  추가하면서 핵심 대화 경험을 다시 정의하는 재작업도 줄입니다.
- 영향: 답글을 대상으로 다시 답할 때 같은 1단 묶음에 추가하고 대상 사용자를 표시할지는
  후속 제품 결정입니다. 삭제 뒤 대화 표시, 답글 알림과 세부 권한도 이후 결과 결정에서
  현재 계층을 전제로 정해야 합니다. 이 결정만으로 생성·조회·수정·삭제 범위나 알림 기능
  포함 여부를 확정하지 않습니다.
- 배제한 대안: 게시글만 제공하면 게시글 안의 대화가 없고, 평면 댓글은 특정 댓글에 직접
  응답하는 핵심 경험을 제공하지 못합니다. 무제한 대댓글과 다단계 화면은 첫 출시에 필요한
  범위보다 대화 탐색과 운영 복잡도가 크므로 현재 범위에서 제외합니다.
- 재검토 조건: 실제 사용과 운영에서 1단 답글의 대화 가치보다 가독성·운영 비용이 크다는
  근거가 확인되거나, 1단으로는 대화 맥락을 유지할 수 없다는 근거가 확인되면 답글 제공
  범위와 표시 깊이를 재검토합니다.

### 활성 결정: 로그인 없이 볼 수 있는 콘텐츠 범위

첫 일반 커뮤니티에서 로그인하지 않은 방문자가 어디까지 읽을 수 있게 할지 결정합니다.

#### A. 게시글·댓글·답글 전체 공개 — 추천

로그인하지 않아도 게시글 목록과 상세, 댓글과 답글을 모두 볼 수 있습니다. 처음 방문한
사용자가 대화 전체를 확인하고 공유된 링크로 바로 들어올 수 있으며, 이후 회원 전용이나
제한 공개 공간을 추가하더라도 현재 일반 커뮤니티의 공개 범위를 유지할 수 있습니다.

#### B. 게시글만 공개

로그인하지 않아도 게시글 목록과 상세는 볼 수 있지만 댓글과 답글은 로그인한 사용자만 볼
수 있습니다. 게시글 유입은 열어 두면서 대화 열람을 가입 동기로 사용할 수 있지만, 방문자는
게시글의 전체 맥락을 확인할 수 없습니다.

#### C. 전체 로그인 필요

게시글 목록부터 댓글과 답글까지 로그인한 사용자만 볼 수 있습니다. 콘텐츠 접근 범위는
가장 강하게 제한하지만, 처음 방문한 사용자가 커뮤니티의 내용과 활동성을 확인하기 어렵습니다.

이 선택은 로그인하지 않은 사용자의 읽기 범위만 결정합니다. 게시글·댓글·답글의 생성·수정·
삭제 범위, 게시판 수, 반응·북마크·알림·이미지와 이후 추가할 제한 공개 공간의 범위는 아직
결정하지 않습니다. 이메일 인증을 완료하지 않은 계정이 일반 보호 기능을 사용할 수 없다는
현재 account 정책도 이 선택으로 바꾸지 않습니다.

응답 형식: `첫 공개 열람=A`, `첫 공개 열람=B` 또는 `첫 공개 열람=C`

선택을 이 본문에 반영한 뒤 다음 결과 정의 결정 하나를 엽니다. 이 선택만으로 해결 설계나
구현 계획을 시작하지 않습니다.
