## 현재 결론과 다음 행동

이 표는 상세 내용보다 먼저, 다음 안정 actor가 대화 없이 행동할 수 있게 씁니다. 한 행에는
하나의 결론·상태·행동만 둡니다. `현재 결론`에는 현재 단계 후보 전체의 단일 판정만 쓰고,
닫힌 범위나 남은 gate를 섞지 않습니다.

| 항목 | 현재 값 |
| --- | --- |
| 현재 단계 | `결과 정의` |
| 현재 결론 | `<검토 가능/결정 필요/차단 등 현재 단계 후보 전체에 대한 단일 판정>` |
| 닫힌 결과 | `<다시 묻지 않을 대상·결과·제약과 보증하지 않는 경계>` |
| 남은 gate | `<gate identity>: <canonical 상태>. <외부 gate이면 owner와 처음 막는 downstream 효과>` |
| 지금 actor | `<모든 gate 뒤 처음 행동할 안정 actor>` |
| 지금 할 일 | `<그 actor가 수행할 exact 행동 하나>` |
| 사용자 차례 | `<지금 필요한 결정 ID 전체/차례가 오는 조건/사용자 작업 없음>` |
| 응답 방식 | `<본문 결합 응답 형식 또는 design의 결정 ID·exact anchor/exact 단계 확정·수정 방식/해당 없음>` |
| 이 행동 뒤 결과 | `<만들어질 artifact·상태와 첫 consumer>` |
| 다음 단계 전환 | `<현재 단계 closure와 다음 단계가 열리는 조건>` |

`남은 gate`가 둘 이상이면 identity별로 행을 반복하고, 없으면 `남은 gate | 없음`을
유지합니다. 사용자가 지금 actor가 아니어도 `사용자 차례`와 `응답 방식`을 삭제하지 않고
각각 `사용자 작업 없음`, `해당 없음`으로 표시합니다. 본문과 `-design`이 함께 존재하면
같은 순서·값을 투영하되 상세 근거는 owner section으로 연결합니다.

### 활성 결정

사용자가 지금 선택해야 하는 제품 결과·범위·수용 값이 있을 때만 이 block 전체를 둡니다. 현재 source와 닫힌
선행 결과로 완전한 후보를 만들 수 있는 독립 결정은 모두 포함합니다. 이미 확정된 결정은
여기서 제거하고 같은 ID의 `결정 색인 > 본문 소유 확정 결과 결정`로 옮기며, 선행 선택 없이는 후보 차이를 만들 수 없는 결정은
아직 질문하지 않습니다. 장기 복원할 기술 결정은 `-design`의 활성 block 한 곳만 소유하고
이 본문의 `응답 방식`이 그 결정 ID와 exact anchor를 가리킵니다.

#### R1. `<한 번의 응답으로 닫을 수 있는 결정 질문>`

결정 질문은 `<현재 맥락에서> <실제 후보 중> <어떤 결과를 정할 것인가?>`로 씁니다.
구현 방법을 모르는 상태나 이미 확정된 값을 질문으로 바꾸지 않습니다.
다른 값을 고정한 채 이 값만 바꿀 수 있거나 다른 consumer·영향·재검토 조건이 생기는 값은
같은 주제·응답 시점이어도 별도 카드로 분리합니다. 여러 카드는 아래 결합 응답 형식으로 함께
받을 수 있지만 한 카드나 비교표에 합치지 않습니다.

- 사용자 소유 근거: `<제품 결과·비용·운영 의사처럼 이 값을 사용자만 정할 수 있는 이유>`
- 공통 전제·제약: `<모든 후보에 같은 source 사실·닫힌 요구·비교 시작 상태>`

| 비교 축 | A. `<실제 후보>` | B. `<실제 후보>` |
| --- | --- | --- |
| `<현재 목표에서 결과를 바꾸는 축>` | `<구체적 구조·행위 → 상태 변화 → 효과·비용·위험>` | `<같은 축과 인과 문법의 실제 차이>` |
| `<두 번째 축>` | `<실제 차이>` | `<실제 차이>` |

- 추천: `<후보 하나>`
- 추천 근거: `<보존할 목표 → 두 후보의 결정적 차이 → 이 후보가 목표를 만족하는 이유>`
- 감수 비용·위험: `<추천을 택할 때 실제로 부담하는 비용과 실패 표면>`
- 재검토 조건: `<관찰 가능한 event/threshold/source 변경 → 다시 열 결정 ID>`

후보가 셋이면 열을 하나 추가합니다. 같은 질문·시작 상태·목표 종료 상태가 아닌 후보는
같은 표에 넣지 않습니다. `장점/단점/기타`나 모든 대안에 같은 설명이 들어가는 축은
비교축이 아닙니다. 장기 기술 대안의 상세 비교는 `-design`이 소유하고, 이 카드는 사용자가
소유한 결과 값만 비교합니다.

#### 결합 응답 형식

`R1=<A 또는 B>, R2=<A 또는 B>`

모든 활성 카드를 한 번에 답할 수 있는 형식은 이곳 하나만 소유합니다. 응답 뒤 만들어질
결과와 다음 단계 전환은 상단 표에만 씁니다.

## 달성할 결과

`<대상/주체>가 <바뀔 상태>가 되며, <보존할 불변식>을 유지하고, <관찰 가능한 결과>로
확인할 수 있습니다.`

성공 조건으로 함께 검증되는지 확인하고, 독립적으로 관찰·복구해야 하면 work item을 나눕니다.

## 범위

- `<포함 표면> → <책임 경계> → <이 결과에 필요한 이유>`

파일 목록을 범위로 대신하지 않습니다. 변경되는 책임과 그 경계를 먼저 쓰고, 파일은 실행
계획에서 source 위치를 식별할 때만 사용합니다.

## 제외 범위

- `<제외 표면> → <보증하지 않는 결과> → <다시 여는 관찰 trigger와 owner>`

`나중에`, `필요 시`처럼 재검토 시점을 복원할 수 없는 표현은 쓰지 않습니다.

## 수용 기준

- [ ] `<조건/입력>에서 <관찰 결과>를 <증거·판정 수단>으로 확인하며, <통과·실패 경계>를 적용합니다.`

각 기준은 달성할 결과나 요구사항 하나 이상과 연결되어야 합니다. 내부 구현 사실만 확인하고
사용자 결과를 입증하지 못하는 기준은 단독 수용 기준으로 두지 않습니다.

### 본문 소유 확정 결과 결정

제품 결과·범위·수용 값처럼 본문이 소유하는 결정만 이곳에 보존합니다. 장기 기술 결정의
상세는 `-design`이 소유하고 위 색인은 exact D anchor만 가리킵니다.

#### R1. `<닫힌 결정이 해결한 질문>`

**결정 질문:** `<당시 맥락에서> <실제 후보 중> <어떤 결과를 정했는가?>`

**공통 전제:** `<모든 후보가 공유한 source 사실·닫힌 요구·시작 상태·목표 종료 상태>`

| 비교 축 | A. `<실제 후보>` | B. `<실제 후보>` |
| --- | --- | --- |
| `<결과를 바꾼 축>` | `<구체적 행위·구조 → 상태 변화 → 사용자·시스템 결과>` | `<같은 축의 실제 차이>` |
| 현재 목표 판정 | `<통과/탈락 → exact 이유>` | `<통과/탈락 → exact 이유>` |

**선택: `<확정 값>`.** `<보존할 목표>`를 유지하려면 `<후보를 가른 결정적 차이>`가 필요하므로
이 값을 선택하고, 그 대신 `<감수 비용·위험>`을 받아들입니다.

- 영향·비보증: `<선택이 바꾸는 결과 / 이 선택만으로 보장하지 않는 결과>`
- 기술 상세 owner: `<이 결과를 구현할 design Dn 또는 기존 SOT / 해당 없음>`
- 재검토 조건: `<관찰 가능한 event·threshold·source 변경 → 다시 열 R ID와 consumer>`

닫힌 질문은 과거의 명령문을 복사하지 않고 해결한 문제를 복원하는 문장으로 씁니다. 당시
후보와 비교축은 실제로 판단에 사용한 것만 보존하며, 사후 대안을 추가하지 않습니다.

## 차단·rollback 변형

계획 중 `Blocked`이면 일반 `계획 단계`를 제거하고 첫 화면을 `현재 결론 → 차단 전 계획
단계 → 닫힌 결과 → blocker identity·상태·owner → 지금 actor·할 일 → 사용자 차례·응답
방식 → 재개할 계획 단계 → closure 조건 → 재개 뒤 결과` 순서로 교체합니다.

선행 결과가 다시 열리면 기존 downstream artifact를 삭제하거나 전부 활성 질문으로 돌리지
않습니다. 결정·artifact별로 `현재 유효`, `부분 재검토 대기`, `전체 재검토 대기` 중 하나를
표시하고, 제외할 decision ID, 첫 downstream consumer, 다시 닫을 조건을 함께 씁니다.
