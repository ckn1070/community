# 자동차 카탈로그 도메인

이 문서는 Carmunity 자동차 카탈로그의 현재 업무 개념, 관계, 상태와 조회 의미를 소유합니다.
정확한 table·column·constraint·index는 [110 자동차 카탈로그 Schema Reference](../project/schema/110-car-catalog.md),
현재 구현 module은 [210 모듈 지도](../project/210-module-map.md)에서 확인합니다.

## 범위

현재 카탈로그는 자동차 백과사전이나 견적 시스템이 아닙니다. 대한민국 시장의 신차와 공개된
과거 차량을 브랜드·모델 기준으로 탐색하고, 비교에 필요한 주요 제품·기술·판매 정보를
읽기 전용으로 제공하는 기능입니다.

포함하는 정보는 다음과 같습니다.

- 브랜드, 모델, 세대와 시장별 모델 연식
- 동력 형식, 연료, 구동·변속, 합산 성능과 주요 동력 장치
- 차체·인승·치수·중량·적재·견인·휠·타이어·섀시가 달라지는 기술 변형
- 실제 판매 트림·채널·판매 기간, 적용일별 기본 가격과 선택 품목
- 측정 조건별 연비·전비·수소 효율, CO₂와 인증 주행거리
- 독립 검색하지 않는 기본 품목·보증·안전도·권리가 확인된 media

VIN 단위 차량, 재고·대리점·구매·견적·보조금, 중고차 매물, 관리자 입력과 crawler, 모든
정정 시점의 감사 이력은 현재 범위가 아닙니다.

## 개념 지도

```text
브랜드
└─ 모델
   └─ 세대
      └─ 모델 연식
         ├─ 동력계통
         │  └─ 구성 장치
         └─ 기술 변형 ── 동력계통
            ├─ 조건별 인증
            └─ 판매 구성
               ├─ 기본 가격 이력
               └─ 선택 품목 이력
```

제품 식별, 기술 사양과 판매 정보는 같은 자동차를 설명하지만 변화 이유와 주기가 다릅니다.
이 세 축을 분리해야 세대·연식이 바뀌어도 모델을 유지하고, 같은 연식의 인승·휠 변형과
트림별 가격 변경을 중복 없이 표현할 수 있습니다.

## 용어와 한 행의 의미

| 개념 | 의미 | 독립된 이유 |
| --- | --- | --- |
| 브랜드 | 여러 모델을 소유하는 제조 브랜드 | 모델 목록의 최상위 탐색 단위입니다. |
| 모델 | K5·카니발·EV6처럼 세대가 바뀌어도 유지되는 제품명 | 세대·연식과 독립된 검색·표시 단위입니다. |
| 세대 | full change, facelift, minor change로 구분하는 상품성 변경 단계 | 한 모델의 변화를 순서대로 보존합니다. |
| 모델 연식 | 한 시장에서 사양과 판매 기간이 유지되는 연식·edition | 같은 세대 안에서도 사양과 판매 기간이 달라집니다. |
| 동력계통 | 연식이 제공하는 엔진·모터·에너지 조합 | 검색에 쓰는 동력 형식·연료와 제조사 시스템 성능을 소유합니다. |
| 구성 장치 | 동력계통 안의 엔진·모터·배터리·연료전지·탱크 한 개 | 한 동력계통에 같은 종류의 장치가 여러 개 존재할 수 있습니다. |
| 기술 변형 | 차체·인승·휠·동력계통 조합으로 제원과 인증이 같은 단위 | 트림명이 같아도 기술 제원과 인증 조건이 달라질 수 있습니다. |
| 판매 구성 | 사용자가 가격표에서 선택하는 트림·판매 채널 | 기술 변형과 판매 기간·기본 품목의 생명주기가 다릅니다. |
| 기본 가격 | 특정 날짜부터 판매 구성에 적용되는 차량 기본 가격 | 가격 변경 뒤에도 과거 기준일 조회가 필요합니다. |
| 선택 품목 | 특정 날짜부터 적용되는 옵션·패키지·유상 색상의 가격과 선택 상태 | 품목별 변경 시점이 기본 가격과 서로 다릅니다. |
| 인증 | 기술 변형의 휠·타이어·카메라·온도 등 측정 조건별 공식 결과 | 같은 변형도 조건에 따라 효율과 주행거리가 달라집니다. |

트림은 판매 구성 밖에서 독립적으로 소비하지 않으므로 별도 개념으로 만들지 않습니다.
국가·시장·통화도 현재 단일 시장 범위에서는 code로 표현하며, 다중 시장 요구가 생길 때만
독립 기준정보로 승격합니다.

## 정보 책임

### 동력계통과 구성 장치

동력계통은 `ICE`, `MHEV`, `HEV`, `PHEV`, `EREV`, `BEV`, `FCEV`와 외부 에너지,
구동·변속, 시스템 전체 출력·토크, 대표 AC·DC 충전 조건을 소유합니다. 구성 장치는 개별
엔진·모터·배터리·연료전지·탱크의 출력·용량·제조 정보를 소유합니다.

시스템 전체 출력은 개별 장치 출력의 단순 합으로 계산하지 않습니다. 제조사가 시스템 값과
장치 값을 각각 공개할 수 있으므로 둘을 별도 사실로 유지합니다. 대표 충전 시간은 AC 한 건과
DC 한 건만 제공하며 충전 곡선이나 다중 조건 비교는 현재 제품 범위가 아닙니다.

### 기술 변형과 판매 구성

기술 변형은 차체, 인승, 치수, 중량, 적재·견인, 휠·타이어와 섀시를 소유합니다. 판매 구성은
트림명, 판매 채널·기간, 공개 여부와 표시 정보를 소유합니다. 같은 기술 변형을 여러 트림이
공유할 수 있으므로 기술 제원을 판매 구성마다 반복하지 않습니다.

기본 품목·보증·안전도·media는 현재 조회에서 표시만 하고 독립 검색·정렬하지 않습니다.
따라서 제한된 구조의 표시 정보로 보존하며, 독립 갱신이나 검색 요구가 생긴 항목만 관계형
개념으로 승격합니다. 유상 색상은 가격과 선택 상태가 있으므로 선택 품목으로 취급합니다.

### 가격과 선택 품목

기본 가격은 판매 구성별 적용 시작일 이력입니다. 기준일에는 그 날짜 이하에서 가장 최근인
한 건을 사용하고, 세제 혜택 후 가격이 있으면 표시 가격으로 우선합니다. 선택 품목도
판매 구성과 품목 code별 가장 최근 상태를 선택하며, 그 행이 선택 가능할 때만 노출합니다.

가격과 선택 품목을 하나의 범용 가격 개념으로 합치지 않습니다. 기본 가격과 추가 금액은
대상 관계, 변경 시점과 무결성 규칙이 다릅니다.

## 상태와 공개 규칙

모델 연식과 판매 구성은 판매 시작일과 종료일을 가집니다. 종료일은 포함하지 않습니다.

| 조건 | 상태 |
| --- | --- |
| 기준일이 시작일보다 이전 | `UPCOMING` |
| 시작일 이상이고 종료일이 없거나 종료일보다 이전 | `ON_SALE` |
| 종료일 이상 | `DISCONTINUED` |

공개 판매 구성이 하나 이상 있을 때만 상위 브랜드·모델·연식을 비회원 조회에 노출합니다.
상위 개념에 같은 공개 flag를 반복하지 않습니다. `is_published`는 제조사의 공개 여부가 아니라
Carmunity가 해당 판매 구성을 공개 API에 노출하도록 검수한 상태입니다.

모델 목록의 여러 filter는 모두 같은 판매 구성을 기준으로 만족해야 합니다. 대표 연식은
조건을 만족한 후보 중 `ON_SALE` → `UPCOMING` → `DISCONTINUED`, 출시일 내림차순, 연식
내림차순, 판매 시작일 내림차순, 공개 식별자 오름차순으로 한 건을 고릅니다.

## 무결성 책임 경계

| 책임 | 보장하는 내용 |
| --- | --- |
| DB schema | 부모 소속, 식별자 중복, 허용 enum-like 값, 한 행 안의 범위·단위·필수값, 다른 연식의 동력계통 연결 금지 |
| 조회 application | 검색 정규화, 같은 판매 구성 filter, 기준일 상태·가격·옵션 선택, 대표 연식과 안정 정렬, 내부 id 비노출 |
| 초기 데이터 검수 | 동력 형식별 필수 장치 완전성, 부모·자식 판매 기간 포함 관계, 가격·옵션 적용일, 원문 조건과 DB 값 대응 |

부모 행을 읽어야 하는 규칙이나 여러 자식 행의 완전성을 단일 row `CHECK`로 흉내 내지
않습니다. 현재 runtime은 읽기 전용이며, 검수된 data migration만 카탈로그를 변경합니다.
모델 상세 Redis cache는 이 PostgreSQL 원본 지위를 바꾸지 않습니다. 현재일의 성공 결과만
최대 5분 재사용하고 과거·미래 snapshot, not-found와 Redis 장애는 원본 조회 의미를 그대로
유지합니다. Runtime writer가 생기면 TTL만으로 freshness를 관리하지 않고 targeted
invalidation을 별도 설계합니다.

## 확장 조건

- 두 번째 국가·통화·시장을 실제 지원할 때 market·currency 기준정보를 분리합니다.
- 옵션 간 필수·배타 조합을 계산하는 견적 기능이 생기면 option identity와 호환 규칙을
  설계합니다.
- 보증·안전도·media를 독립 검색·갱신하면 해당 표시 정보만 관계형 구조로 승격합니다.
- 관리자 입력과 모든 정정 시점 복원이 필요하면 writer 권한·감사·version 정책을 별도
  설계합니다.
- 실제 query plan이 현재 관계형 조회 목표를 충족하지 못할 때만 검색 read model, cache나
  검색엔진을 검토합니다.
