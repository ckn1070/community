# Account 인증/인가 Schema Reference

이 문서는 account/auth 관련 Flyway migration을 모두 적용한 뒤의 현재 DB schema 최종 상태를 테이블 단위로 정리합니다.

## 문서 내 진입점

| 확인할 내용 | 위치 |
| --- | --- |
| 권위 자료와 적용 migration | [Source Of Truth](#source-of-truth), [Migration 목록](#migration-목록) |
| account와 인증 주체 기본 구조 | [account](#account), [account_profile](#account_profile), [account_password_credential](#account_password_credential) |
| role과 session token 구조 | [auth_role](#auth_role), [account_role_assignment](#account_role_assignment), [refresh_token](#refresh_token) |
| 소유권 확인·관리자 초대·감사 이벤트 | [account_verification_token](#account_verification_token), [admin_invitation](#admin_invitation), [auth_event](#auth_event) |
| migration 추가 시 문서 갱신 | [갱신 규칙](#갱신-규칙), [문서 구조 기준](#문서-구조-기준) |

## 목적

- 하나의 테이블이 여러 migration에 걸쳐 변경되더라도 현재 column, constraint, index 상태를 빠르게 확인합니다.
- 구현자가 entity, query, 테스트를 작성할 때 현재 DB contract를 한곳에서 볼 수 있게 합니다.
- 운영자가 schema 상태를 확인할 때 migration 파일을 매번 조립해서 읽지 않아도 되게 합니다.

## Source Of Truth

Flyway migration 파일이 DB schema의 source of truth입니다.
이 문서는 source of truth가 아니라, migration들을 적용한 결과를 사람이 읽기 쉽게 모은 reference입니다.

| 구분 | 책임 |
| --- | --- |
| Flyway migration | 실행 가능한 schema 변경 이력과 적용 순서를 소유합니다. |
| 이 문서 | 현재 최종 schema 상태를 테이블별로 요약합니다. |
| 데이터 모델 문서 | 왜 이런 테이블과 관계가 필요한지 설명합니다. |

schema를 바꾸는 migration을 추가하면 같은 작업에서 이 문서도 함께 갱신합니다.
적용된 versioned migration은 수정하지 않고, 변경은 새 migration과 이 reference 갱신으로 반영합니다.
다만 [009 비카탈로그 DDD 보완 설계](../../work-items/improvements/2026/009-non-catalog-ddd-hardening-design.md#결정-4-데이터-전환-방식)는
모든 적용 환경의 DB와 Flyway 이력을 폐기하고 빈 DB를 다시 만드는 일회성 전환을 명시적으로
선택했으므로 V6·V7을 최종 schema로 다시 정의합니다. 이 선택은 지속 DB에 재사용하는 migration
수정 절차가 아닙니다.

현재 V7·V10에는 이 기준을 위반한 Auth Event taxonomy 직접 수정 이력이 있습니다. 신규 DB의
최종 schema 설명은 이 reference와 일치하지만, 이전 checksum으로 migration을 적용한 지속
DB의 호환성은 확인되지 않았습니다. 현재 결함 경계와 안전한 전환 기준은
[240 Flyway](../../tech-stack/240-flyway.md#현재-알려진-migration-호환성-결함)가 소유하며,
[001 Auth Event Taxonomy 재설계](../../work-items/improvements/2026/001-auth-event-taxonomy-redesign.md)는
영향 확인과 수정 작업 상태를 추적합니다.

## 공통 규칙

- 테이블명은 단수형입니다.
- 내부 PK는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`를 기본으로 사용합니다.
- 외부 노출 식별자는 `public_id`처럼 별도 UUID column을 사용합니다.
- timestamp 기본값은 insert fallback 용도의 `DEFAULT NOW()`입니다.
- `created_at`, `updated_at`을 함께 가진 테이블은 `updated_at >= created_at` check constraint를 둡니다.
- enum-like 값은 PostgreSQL native enum이 아니라 `VARCHAR`와 `CHECK` constraint로 고정합니다.
- FK의 delete/update action은 migration에 별도로 지정하지 않았으므로 PostgreSQL 기본 동작을 따릅니다.

## account

관리자와 일반회원을 포괄하는 인증 주체 table입니다.

관련 migration: `V1__create_account_table.sql`

### Columns

| column | type | nullable | default | 의미 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | no | identity | 내부 PK |
| `public_id` | `UUID` | no | 없음 | 외부 API와 token subject에 쓰는 공개 식별자 |
| `email` | `VARCHAR(254)` | no | 없음 | 현재 `EmailAddress`가 trim·lowercase한 저장·응답 email |
| `email_normalized` | `VARCHAR(254)` | no | 없음 | 중복 판단용 정규화 email |
| `status` | `VARCHAR(20)` | no | 없음 | account 생명주기 상태 |
| `email_verified_at` | `TIMESTAMPTZ` | yes | 없음 | email 인증 완료 시각 |
| `last_login_at` | `TIMESTAMPTZ` | yes | 없음 | 마지막 로그인 성공 시각 |
| `created_at` | `TIMESTAMPTZ` | no | `NOW()` | 생성 시각 |
| `updated_at` | `TIMESTAMPTZ` | no | `NOW()` | 마지막 갱신 시각 |
| `withdrawn_at` | `TIMESTAMPTZ` | yes | 없음 | 탈퇴 완료 시각 |

### Constraints

| name | type | definition | 의미 |
| --- | --- | --- | --- |
| `pk_account` | primary key | `(id)` | 내부 row 식별자 |
| `uk_account_public_id` | unique | `(public_id)` | 외부 노출 식별자 중복 방지 |
| `uk_account_email_normalized` | unique | `(email_normalized)` | email 대소문자 차이 중복 방지 |
| `chk_account_status` | check | `status IN ('PENDING', 'ACTIVE', 'SUSPENDED', 'WITHDRAWN')` | account 상태 허용값 |
| `chk_account_updated_at` | check | `updated_at >= created_at` | 감사 timestamp 역전 방지 |
| `chk_account_withdrawn_at` | check | `WITHDRAWN`이면 `withdrawn_at` not null, 아니면 null | 탈퇴 시각 정합성 |

### Indexes

별도 index는 없습니다.
PK와 unique constraint가 생성하는 index만 사용합니다.

### Sensitive Data

`email`과 `email_normalized`는 현재 같은 trim·lowercase 개인정보입니다. 원래 casing은 보존하지 않습니다.
password, access token, refresh token 원문은 저장하지 않습니다.

### Columns

## refresh_token

Base64URL opaque refresh token의 SHA-256 hash와 rotation 상태를 저장하는 table입니다.

관련 migration: `V6__create_refresh_token_table.sql`

### Columns

| column | type | nullable | default | 의미 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | no | identity | 내부 PK |
| `account_public_id` | `UUID` | no | 없음 | refresh token 소유 account의 공개 식별자 |
| `token_hash` | `CHAR(64)` | no | 없음 | refresh token SHA-256 hash |
| `family_id` | `UUID` | no | 없음 | refresh token rotation family 식별자 |
| `issued_at` | `TIMESTAMPTZ` | no | `NOW()` | 발급 시각 |
| `expires_at` | `TIMESTAMPTZ` | no | 없음 | 만료 시각 |
| `last_used_at` | `TIMESTAMPTZ` | yes | 없음 | 정상 rotation에 마지막으로 사용된 시각 |
| `revoked_at` | `TIMESTAMPTZ` | yes | 없음 | 폐기 시각 |
| `revoked_reason` | `VARCHAR(50)` | yes | 없음 | 폐기 사유 |
| `replaced_by_token_id` | `BIGINT` | yes | 없음 | rotation으로 대체된 새 token row id |
| `ip_address` | `INET` | yes | 없음 | 발급 또는 사용 IP |
| `user_agent` | `VARCHAR(512)` | yes | 없음 | 발급 또는 사용 User-Agent |

### Constraints

| name | type | definition | 의미 |
| --- | --- | --- | --- |
| `pk_refresh_token` | primary key | `(id)` | 내부 row 식별자 |
| `fk_refresh_token_account_public_id` | foreign key | `account_public_id REFERENCES account(public_id)` | public-id application writer의 account 참조 |
| `fk_refresh_token_replaced_by_token` | foreign key | `replaced_by_token_id REFERENCES refresh_token(id)` | rotation 대체 token |
| `uk_refresh_token_token_hash` | unique | `(token_hash)` | token hash 중복 방지 |
| `chk_refresh_token_hash` | check | `token_hash ~ '^[0-9a-f]{64}$'` | SHA-256 hex hash 형식 |
| `chk_refresh_token_expires_at` | check | `expires_at > issued_at` | 만료 시각 정합성 |
| `chk_refresh_token_last_used_at` | check | `last_used_at IS NULL OR last_used_at >= issued_at` | 사용 시각 정합성 |
| `chk_refresh_token_revoked_at` | check | `revoked_at IS NULL OR revoked_at >= issued_at` | 폐기 시각 정합성 |
| `chk_refresh_token_revoked_reason` | check | 활성 token은 reason null, 폐기 token은 허용 reason 필요 | 폐기 상태와 사유 정합성 |
| `chk_refresh_token_replaced_by` | check | `replaced_by_token_id IS NULL OR replaced_by_token_id <> id` | 자기 자신으로 대체 금지 |

### Allowed Values

`revoked_reason` 허용값은 다음과 같습니다.

- `LOGOUT`
- `ROTATED`
- `REUSE_DETECTED`
- `PASSWORD_CHANGED`
- `ACCOUNT_SUSPENDED`
- `ADMIN_REVOKED`

### Indexes

| name | type | columns | predicate | 목적 |

## 갱신 규칙

다음 변경이 생기면 같은 작업에서 이 문서를 갱신합니다.

- table 추가, 삭제, 이름 변경
- column 추가, 삭제, 이름 변경, type 변경, nullability 변경, default 변경
- primary key, foreign key, unique, check constraint 변경
- index 추가, 삭제, column 순서 변경, partial predicate 변경
- enum-like check 허용값 변경
- seed data 추가, 삭제, 값 변경
- 민감정보 저장 정책 변경

문서 갱신 시에는 새 migration 파일만 보지 않고, 해당 table의 최종 상태가 어떻게 바뀌는지 기준으로 정리합니다.
한 table에 여러 migration이 쌓여도 이 문서에는 최종 schema 상태를 씁니다.
변경 이력 자체는 Flyway migration이 소유합니다.

[430 Application 기능 qualification](../../operations/430-application-functional-qualification-runbook.md)의
staging cleanup SQL은 현재 account/auth FK와 허용 taxonomy를 직접 소비합니다. 위 table·FK,
role assignment, verification token, auth event 또는 admin invitation 관계가 바뀌면 같은
schema 작업에서 `430`의 대상 guard와 child-first 삭제 순서를 함께 대조·갱신합니다. SQL
전문은 이 Schema Reference에 복제하지 않습니다.
